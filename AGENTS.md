# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository: the Hugo source of **https://openms.de**.

## What this is

- A static site built with **Hugo extended** and deployed by **Netlify** (every merge to `main` rebuilds the site; every pull request gets a **Deploy Preview**).
- The base theme is the git submodule `themes/scientific-python-hugo-theme/`. **Never edit the theme**: override it in `layouts/` and `assets/`.
- Most visible text lives in **`config.yaml`** (under `languages.en.params`), not in the page files.
- `docs/` is maintainer documentation written for **non-developers**. Keep it in sync with the code (see *Documentation* below).

## Commands

```bash
git submodule update --init --recursive   # once: fetch the theme
make serve                                 # dev server on http://localhost:1313 (hugo server -D)
make html                                  # build into ./public
```

- Netlify builds with **Hugo 0.155.0** (`netlify.toml`). Avoid Hugo features newer than that.
- The dev server writes to `public/` and **never deletes** pages you removed. To check that a page is really gone, build into an empty folder: `hugo --destination /tmp/openms-build` and look there.
- `static/_redirects` is read **only by Netlify**. Redirects cannot be tested locally; test them on the Deploy Preview.

## Where things live

| Path | What it is |
|------|-----------|
| `config.yaml` → `languages.en.params` | Text and lists for almost every block: `hero`, `homeMetrics`, `keyfeatures`, `navbar`, `footer`, `newsBanner`, `webapps`, `affiliateProjects`, `archivedProjects`, `universityPartners`, `sponsorTiers`, `<page>Page` intros… |
| `content/en/*.md` | One file per page. Many contain only front matter; their design is chosen by file name (next row). |
| `layouts/_default/single.html` | Routes each page by `.File.BaseFileName` to `layouts/partials/<name>-main.html`. A new page needs a branch here or it falls back to the plain content template. |
| `layouts/partials/`, `layouts/shortcodes/` | Page designs and building blocks. Some page text is hard-coded here (Governance, Contact, Press kit, Sponsorship FAQ, board of directors). |
| `layouts/index.html` | Home page: the order of its blocks. |
| `assets/css/` | Load order: theme CSS → `css/*.css` → `css/openms-overrides.css` → `css/overrides/*.css` (page-specific, loaded last). Put page fixes in `css/overrides/<page>.css`. |
| `assets/js/*.js` | **All** files are concatenated into one bundle on every page. Guard page-specific code (check the element exists). |
| `static/` | Served as is (`static/images/foo.png` → `/images/foo.png`). |
| `static/gallery/members.html` | The Executive Committee on `/contributors/`, **edited by hand** (not generated by `make teams`). |
| `data/community_events.yaml` | Calendar events, **generated** from the OpenMS Google Calendar. Never edit by hand: the sync replaces the whole list. |
| `static/_redirects` | Netlify redirects, including short links printed in papers (`/nuxl`, `/flashdeconv`…). Keep both the `/path` and `/path/` forms. |
| `images/` (top level) | **Not published.** Archive copies only. See `docs/reference/archive-folders.md`. |

The full map of every navbar and footer link to its page file, layout, words and CSS is in `docs/reference/file-locations.md`.

## Pitfalls found the hard way

- **`sponsorTiers.benefitsMatrix`**: every row must have a key for **every** level `id` (use `[]` for "not included"). A missing key fails the build (`len $cell` on nil in `sponsor-tiers.html`). Level cards show only the **first 3** benefits of each level, in row order.
- **App card buttons** (`layouts/partials/webapps-project-links.html`): no limit, but they wrap. Featured cards fit 3 per line at laptop width, Affiliated cards 2. `github` links are always moved last; all buttons open in a new tab. Only the **first** button of a card is filled, the others are outlined. This is set by position-only rules (`#app-card-buttons` in `assets/css/overrides/featured-apps.css`, #58): never colour a button by its type.
- **Dead config**: `homeSponsors`, `homePage.pathways`, `heroGroup` and `hero.microcopy` are not rendered anywhere. `index.html` references `partial "panel.html"`, which does **not exist**: never set `params.panel`. `fellowshipPage.projects*` is not rendered. `layouts/partials/contributors-exec.html` is unused.
- **`universityPartners`** feeds both the home page logo strip and the Research Partnerships "Our partners" grid. A change shows in both.
- **The footer year** is `{{ now.Year }}`, set at build time unless a script updates it client-side.
- **Images in `universityPartners`** get `?v=trim1` appended. To replace a logo reliably, upload it under a new file name.
- `content/en/privacy.md`: the page is built by splitting on `###` / `####` headings. Keep them.

## Documentation (`docs/`)

When you change a `config.yaml` key, a layout's editable text, or where something lives, update the matching guide.

- Audience: non-developers editing on GitHub in the browser. Plain language, short sentences, no jargon (or explain it: see `docs/getting-started/words-we-use.md`).
- Structure: `docs/common-tasks/<page>/` has **one folder per page** of the navbar and footer, one task file per thing you can change. `docs/common-tasks/README.md` lists them in menu order; `docs/README.md` has the same table. Add new guides to both.
- Every task guide has a numbered screenshot of the page next to a numbered picture of the matching `config.yaml` / file lines (red boxes and badges, same numbers in both). Images go in `docs/common-tasks-screenshot-images/<folder>/`.
- Say clearly what is **not** editable without the web team (text hard-coded in `layouts/`).
- Before committing docs, check that every relative link and `#anchor` in `docs/` resolves (GitHub heading slugs: lower case, spaces → `-`, punctuation dropped).

## Pull requests

- Small, focused PRs. Describe what changed, how you checked it, and what you could **not** check (for example redirects, which only run on Netlify).
- Check the result on the Netlify Deploy Preview: the home page and one inner page at least, plus every page you touched, at desktop and phone width.
